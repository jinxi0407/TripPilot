验收日期：2026-09-22。稳定 V0.2 checkpoint：`209918f`（`chore: checkpoint stable TripPilot v0.2`）；开发分支：`feat/v1.1-agent-protocols-harness`。未 push、merge 或删除 checkpoint，旧 V0.1/V0.2 OpenSpec change 无修改。

## 实际实现

- 官方稳定 SDK：[`mcp==2.2.0`](https://pypi.org/project/mcp/2.2.0/)、[`a2a-sdk[http-server]==1.1.5`](https://pypi.org/project/a2a-sdk/1.1.5/)，均锁定依赖；`pip check` 通过。安装时按官方 PyPI 当前非预发布、非撤回版本核对，调用已安装版本的官方 API。
- MCP：独立 Streamable HTTP 服务，真实 discovery 和 structured invocation。五个工具：`search_rail`、`search_poi`、`get_weather`、`calculate_distance`、`plan_route`；复用已有 Provider。
- A2A：两个独立服务及标准 Agent Card，官方 JSON-RPC Message → Task → Artifact。Supervisor 所在图节点验证技能和 endpoint，调用专家，再验证类型化结果、用量和允许的 State 字段。
- Transport Card：`TripPilot Transport Agent`，技能 `rail-search`、`transfer-analysis`、`transport-feasibility`。
- Local Card：`TripPilot Local Travel Agent`，技能 `poi-search`、`weather-search`、`local-route-planning`、`distance-calculation`。
- Harness：统一 step/replanning/tool/model/external 预算、deadline、timeout/retry、白名单、重复保护、Pydantic 校验、fallback、elapsed 与失败原因；接入原有 ReAct 和 Critic。仍是原来的五个逻辑 Agent。
- 协议服务和主 API 的实际启动、健康探测、离线 UI 状态都已验证；显式 Mock 保持 V0.2 本地路径。

## LIVE 浏览器验收

实际 Qwen `qwen-plus`、高德 Web Service/JS Map、Rail Dataset，以及独立 MCP/A2A 服务均参与运行。没有用拦截响应模拟协议或 LIVE Provider。Agent Trace 仅为执行摘要，不含私有推理。

| 场景 | 返回 | 实际协议 | 工具/模型/外部调用 | 耗时 |
|---|---|---|---|---|
| 五天三城，4000元 | `partial`，Critic `valid=true`，五天结果 | MCP CONNECTED，A2A 2/2 ONLINE | 24 / 3 / 55 | 34.672秒 |
| 模拟暴雨 | `partial`，`valid=true`，室内替换，1次重规划 | MCP CONNECTED，A2A 2/2 ONLINE | 24 / 4 / 56 | 37.321秒 |
| 预算200元 | `conflict`，`valid=false`，2次重规划后明确预算不可满足 | MCP CONNECTED，A2A 2/2 ONLINE | 24 / 5 / 57 | 39.462秒 |
| MCP 真实暂停超时 | `partial`，`valid=true`，五天结果；明确 MCP FALLBACK | A2A 2/2 ONLINE，本地 Provider 降级 | 24 / 3 / 34 | 121.745秒 |

四个场景均为 Qwen LIVE、Amap LIVE、Rail DATASET、Harness ACTIVE。耗时为本次记录，不能用作普遍性能保证或提升百分比。外部调用是应用层操作预算，包含协议与 Provider 外发，不等于底层 TCP 包数。

正常场景的真实执行记录包含 Supervisor → A2A Transport Agent → MCP search_rail → Rail DATASET，以及 A2A Local Travel Agent → MCP search_poi → Amap LIVE，随后 Travel Planner ReAct → Critic → Final Itinerary。

故障场景对当前启动器的 MCP 进程执行 `SIGSTOP`，触发真实等待超时、Harness 重试和本地 fallback；`finally` 中 `SIGCONT` 恢复。页面明确显示 `MCP FALLBACK`，没有冒充 MCP 成功。恢复后重新探测为 MCP CONNECTED、两 A2A ONLINE，见 [健康证据](v11-health-check.json)。健康接口本身不付费调用 Qwen/高德，故其 Provider 为 PENDING；每次运行的 LIVE 标签来自实际结果。

真实地图在 Day 1、3、5 分别验证杭州、南京、苏州的当前 POI、Marker 名称、真实底图与视野覆盖。两组 LIVE 浏览器验收均为 console errors=0、page errors=0、HTTP errors=0。四个后端服务日志未发现 ERROR 或 traceback，包括受控故障期间。

证据：[三场景浏览器检查](v11-browser-check.json)、[超时降级浏览器检查](v11-fallback-browser-check.json)、[正常结果](v11-demo-normal.json)、[暴雨结果](v11-demo-rain.json)、[预算冲突](v11-demo-budget.json)、[超时降级结果](v11-demo-fallback.json)、[正常截图](screenshots/v11-live-normal.png)、[降级截图](screenshots/v11-live-fallback.png)。这些均为公开运行状态和安全执行摘要。

## 配置与安全

本地 `.env` 未改写、未复制、未加入 Git；`.env.example` 仅空占位符。内部扫描当前待提交文件、服务日志及客户端构建产物，未发现真实凭据外泄；浏览器所需 JS Key 只进入已忽略的客户端产物，后端 Key 和安全码均不进入客户端。扫描只输出计数/状态，不输出凭据，见 [扫描结果](v11-safety-check.json)。

`QWEN_CHAT_MODEL` 保持 canonical，兼容旧 `QWEN_MODEL`；模型为 `qwen-plus`。配置读取仓库根目录 `.env`，协议 URL 和 RuntimePolicy 集中配置。安全码继续由后端地图代理使用。所有服务只监听本机，不新增鉴权、数据库、队列或其他 Agent。
